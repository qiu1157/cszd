# 充电站修改地址操作日志未记录问题排查指南

## 问题现象
充电站 ST-202608-0001 修改了地址,但历史时间线上没有任何信息。

## 快速排查步骤

### 第一步: 检查数据库是否有记录

执行以下SQL查询:

```sql
-- 1. 先找到充电站ID
SELECT id, station_code, station_name, address 
FROM biz_station 
WHERE station_code = 'ST-202608-0001';

-- 2. 假设充电站ID是1,查询该站点的操作日志
SELECT 
    id,
    operator_account,
    target_type,
    target_id,
    target_name,
    operation_type,
    created_at
FROM biz_operation_log
WHERE target_type = 'STATION' AND target_id = 'ST-202608-0001'
ORDER BY created_at DESC;

-- 3. 查看最近10条操作日志(任何类型)
SELECT 
    id,
    operator_account,
    target_type,
    operation_type,
    created_at
FROM biz_operation_log
ORDER BY created_at DESC
LIMIT 10;
```

**判断标准**:
- ✅ 如果能找到UPDATE类型的日志 → **数据库有记录,前端显示问题,跳到第五步**
- ❌ 如果完全没有这条日志 → **继续第二步**
- ❌ 如果表里没有任何记录 → **AOP切面未生效,跳到第三步**

### 第四步: 根据日志诊断问题

#### 情况A: 完全没看到 "OperationLogAspect 开始执行"
**原因**: AOP切面未生效

**解决方案**:
1. 检查 `OperationLogAspect` 类上是否有 `@Aspect` 和 `@Component` 注解
2. 检查主启动类是否有 `@SpringBootApplication` 注解
3. 清理重新编译: `gradlew clean build`

#### 情况B: 看到 "未获取到登录用户信息"
**原因**: 用户认证信息未正确传递

**解决方案**:
1. 检查登录是否成功
2. 检查认证拦截器是否正确设置了 `request.setAttribute(AuthService.CURRENT_USER_REQUEST_ATTRIBUTE, loginUser)`
3. 确认 `AuthService.CURRENT_USER_REQUEST_ATTRIBUTE` 常量值

#### 情况C: 看到 "捕获修改前状态: null"
**原因**: BeforeStateHolder 未正确设置或被清除

**解决方案**:
1. 检查 `StationCommandService.updateStation` 方法中是否调用了 `BeforeStateHolder.set(cloneStation(station))`
2. 确认没有在其他地方提前调用 `BeforeStateHolder.clear()`

#### 情况D: 看到 "操作日志保存失败"
**原因**: 数据库保存异常

**解决方案**:
1. 查看完整的异常栈信息
2. 检查数据库连接是否正常
3. 检查 `biz_operation_log` 表结构是否正确

#### 情况E: 看到 "操作日志保存成功" 但数据库没有记录
**原因**: 事务回滚

**解决方案**:
这是最可能的原因!修改 `OperationLogService` 的事务传播机制:

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)  // 改为独立事务
public void log(...) {
    // ... 原有代码
}
```

## 最可能的原因和解决方案

根据代码分析,**最可能的原因是事务回滚**:

### 问题原因
`OperationLogService.log` 使用 `@Transactional(propagation = Propagation.REQUIRED)`,这意味着:
- 如果主业务方法抛出异常,操作日志会一起回滚
- 如果操作日志保存失败,主业务也会回滚

### 立即解决方案

修改 `OperationLogService.java`:

```java
@Service
public class OperationLogService {
    
    // 将 REQUIRED 改为 REQUIRES_NEW
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void log(
            String operatorAccount,
            String operatorRole,
            OperationTargetType targetType,
            String targetId,
            String targetName,
            OperationType operationType,
            Object beforeState,
            Object afterState,
            String remark,
            Long stationId
    ) {
        // ... 原有代码不变
    }
}
```

```bash
.\gradlew bootRun
```

## 1. 文档目标

本文件用于定义充电站管理系统第一期的产品范围、业务规则、页面结构、角色权限、核心数据模型和技术基线，作为后续任务拆解与开发验收的统一依据。

## 2. 产品定位

建设一个面向内部管理人员使用的充电站管理系统，支持公网访问，采用统一 Web 后台同时兼容 PC 与手机自适应访问。

第一期目标：

* 支持充电站、充电桩、股东、持股关系的统一管理。

* 支持系统管理员与业务管理员的权限分工。

* 支持关键业务事件、状态变更、账号与平台维护的日志审计。

* 支持在页面内查看历史变化时间线。

* 为后续外部平台对接和单枪扩展预留数据结构。

## 4. 角色与权限

### 4.1 系统管理员

* 默认账号：`admin`

* 初始化密码：默认初始化为 `123456`；本地开发可通过私有配置文件或环境变量提供数据库连接，生产环境必须通过部署配置覆盖密码与连接信息

* 可登录系统

* 可修改本人密码

* 可创建业务管理员

* 可重置业务管理员密码

* 重置业务管理员密码时由系统管理员手动输入新密码，新密码需为 `6-20` 位且必须同时包含字母和数字

* 可启用或停用业务管理员

* 可维护系统字典

* 可查看全局操作日志

* 不允许维护充电站、充电桩、股东、持股关系等业务数据

* 登录成功后默认进入首页概览页

### 4.2 业务管理员

* 使用手机号作为登录账号

* 由系统管理员手工创建

* 首次登录不强制修改初始密码

* 可修改本人密码

* 可维护全部充电站业务数据

* 可维护全部充电桩业务数据

* 可维护股东主档

* 可建立与调整持股关系

* 可查看全局操作日志

### 4.3 数据权限

* 业务管理员为全站可管模式。

* 所有业务管理员可查看并维护所有充电站、充电桩、股东及持股关系。

## 5. 技术基线

* 前端：`Vue 3 + Element Plus`

* 后端：`Java`

* 数据库：`MySQL`

* 部署方式：公网部署

* 登录方式：账号密码登录

* 终端策略：同一套 Web 后台自适应兼容 PC 与手机

* 认证口径：所有用户登录均以数据库用户表为准，不允许回退到内存账号

* 本地配置口径：允许使用 `.gitignore` 忽略的 `application-local.yml` 维护本机数据库连接，但不得提交真实密码到仓库

### 5.1 数据库命名规范

* 系统域表统一使用 `sys_` 前缀，例如：`sys_user`、`sys_dict_type`、`sys_dict_item`

* 业务域表统一使用 `biz_` 前缀，例如：`biz_station`、`biz_pile`、`biz_shareholder`

* 业务关联表统一使用 `biz_` 前缀，例如后续 `biz_station_shareholder_relation`

* 所有主键字段统一使用 `id`

* 审计字段统一使用 `created_at`、`updated_at`

* 业务对象唯一编号统一使用 `xxx_code`

* 业务对象名称统一使用 `xxx_name`

* 外部平台侧业务编号统一使用 `platform_xxx_code`

* 引用系统字典项统一使用 `xxx_item_id`

* 引用主档实体统一使用 `xxx_id`

* 唯一键统一命名为 `uk_表名_字段`

* 普通索引统一命名为 `idx_表名_字段`

* 外键统一命名为 `fk_表名_字段`

## 6. 信息架构

### 6.1 顶层菜单

* 首页

* 充电站管理

* 股东管理

* 系统字典

* 操作日志

* 用户管理

* 我的账号

### 6.2 首页

首页采用“数据概览 + 快捷入口”模式。

展示内容：

* 充电站总数

* 充电站状态统计

* 充电桩总数

* 充电桩状态统计

* 股东总数

快捷入口：

* 新增充电站

* 进入股东管理

* 查看操作日志

* 进入系统字典

### 6.3 充电站管理

采用 `列表 + 详情页` 结构。

列表页能力：

* 按名称搜索

* 按平台筛选

* 按状态筛选

* 分页浏览

* 进入详情

* 新增充电站

表单约束：

* 新增 / 编辑充电站表单中的“所在平台”控件属于充电站管理范围实现。

* “所在平台”选项必须复用系统字典中 `PLATFORM` 类型的启用字典项。

详情页采用单页分区结构，包含：

* 基础信息

* 充电桩管理

* 股东信息

* 历史变化时间线

### 6.4 股东管理

股东为独立实体，需提供独立菜单。

列表页能力：

* 按股东名称搜索

* 按状态筛选

* 新增股东

* 编辑股东

* 下载股东导入模板（Excel）

* 导入股东（批量新增）

* 进入股东详情

股东导入能力：

* 提供 Excel 模板下载，模板为三列：股东名称（必填）、联系人（选填）、联系电话（选填）。

* 导入仅新增股东：以股东名称为业务主键做去重与存在性校验，已存在的名称不导入（不允许修改）。

* 导入不执行任何修改或删除操作。

* 导入需做数据验证：任一数据非法则整体不落库，并返回逐行错误（含行号与原因）。

* 模板下载对系统管理员与业务管理员均可见；导入入口仅系统管理员可见且后端强制校验。

股东详情页能力：

* 查看股东基础信息

* 查看该股东关联的充电站

* 查看该股东的历史变化时间线

* 时间线默认展示全部站点事件

* 支持按充电站筛选

### 6.5 系统字典

系统字典为独立页面，仅系统管理员可维护。

页面路由：

* 正式路由为 `/system-dictionaries`

* 兼容旧路由 `/platforms` 自动跳转到 `/system-dictionaries`

第一期覆盖范围：

* 平台

* 充电站状态

* 充电桩状态

第一期页面边界：

* 页面不开放新增字典类型

* 页面仅管理预置字典类型下的字典项

* 列表页采用“标题 + 顶部字典类型下拉 + 表格”结构

字典项统一维护字段：

* 名称

* 编码

* 状态

* 排序

### 6.6 用户管理

仅系统管理员可见。

支持：

* 新增业务管理员

* 查看业务管理员列表

* 列表展示最后登录时间

* 重置业务管理员密码

* 启用或停用业务管理员

### 6.7 操作日志

提供独立全局日志中心。

支持：

* 按时间筛选

* 按操作人筛选

* 按对象类型筛选

* 按充电站筛选

* 查看事件详情

* 密码哈希

* 角色

* 状态

* 是否默认管理员

* 最后登录时间

* 更新时间

规则：

* 业务管理员使用手机号作为登录账号。

* 所有用户登录成功后都要更新最后登录时间。

### 7.1 系统字典

字段建议：

* 字典类型主键ID

* 类型编码

* 类型名称

* 类型状态

* 类型排序

* 字典项主键ID

* 字典项所属类型ID

* 字典项编码

* 字典项名称

* 字典项状态

* 字典项排序

* 创建时间

* 更新时间

说明：

* 第一阶段内置 `PLATFORM`、`STATION_STATUS`、`PILE_STATUS` 三类字典类型。

* 页面不开放新增字典类型，但数据库结构允许后续扩展。

* 平台、充电站状态、充电桩状态均由系统管理员统一维护。

* 同一字典类型下，字典项编码唯一、字典项名称唯一。

* 第一阶段不保存 API 地址、密钥等对接参数。

### 7.2 充电站

字段建议：

* 主键ID

* 充电站编号

* 充电站名称

* 所在平台

* 平台站点编号

* 地址

* 联系人

* 联系电话

* 生命周期状态

* 创建时间

* 更新时间

数据库落地字段：

* 表名：`biz_station`

* 主键：`id`

* 充电站编号：`station_code`

* 充电站名称：`station_name`

* 所在平台字典项：`platform_item_id`

* 平台站点编号：`platform_station_code`

* 地址：`address`

* 联系人：`contact_name`

* 联系电话：`contact_phone`

* 生命周期状态字典项：`station_status_item_id`

* 创建时间：`created_at`

* 更新时间：`updated_at`

规则：

* `充电站编号` 由系统自动生成，且全局唯一。

* `平台站点编号` 由人工录入，可为空。

* `平台站点编号` 在同一平台内唯一。

* 所在平台必须从系统字典中的平台类型中选择。

* 充电站表单中的平台选择控件在充电站管理阶段实现，不作为系统字典独立交付物。

生命周期状态：

* 签合同

* 建设中

* 运营中

* 运营异常

* 停用

状态规则：

* 单一状态

* 允许任意切换

* 状态变更备注为可选

* 状态变更备注最多 500 字符

* 新增默认状态为 `签合同`

* 状态切换入口位于充电站详情页，通过 `PUT /api/stations/{stationId}/status` 完成

* 每次状态变更将原状态、新状态、备注、操作人账号一并写入 `biz_station_status_log` 状态变更日志表

* 历史变化时间线展示状态变更日志，在后续时间线任务中实现

### 7.3 充电桩

字段建议：

* 主键ID

* 桩编号

* 所属充电站ID

* 充电类型

* 充电枪数量

* 生命周期状态

* 创建时间

* 更新时间

规则：

* 当前管理粒度为桩级，不管理单枪明细。

* 需预留未来扩展到枪级的能力。

* 桩编号由系统自动生成。

* 桩编号全局唯一。

生命周期状态：

* 运营中

* 运营异常

* 停用

状态规则：

* 单一状态

* 允许任意切换

* 状态变更备注为可选

* 新增默认状态为 `运营中`

### 7.4 股东主档

字段建议：

* 主键ID

* 股东名称（业务主键，全局唯一）

* 联系人

* 联系电话

* 状态

* 创建时间

* 更新时间

规则：

* 股东为独立主档实体。

* 股东名称为业务主键，全局唯一：新增股东与批量导入均做名称查重，数据库层以唯一索引兜底。

* 一个股东可关联多个充电站。

* 同一股东在不同充电站共享同一份主档信息。

* 股东主档停用后，不能再新建持股关系。

状态：

* 启用

* 停用

说明：

* `退股` 不属于股东主档状态。

* 退股发生在持股关系层面。

### 7.5 持股关系

字段建议：

* 主键ID

* 充电站ID

* 股东ID

* 股份占比

* 关系状态

* 生效时间

* 创建时间

* 更新时间

关系状态：

* 持股中

* 已退出

规则：

* 单条持股占比强制限制在 `0% ~ 100%`：前端输入框限制（不低于 `0%`、不高于 `100%`）与服务端校验双重兜底。

* 持股占比合计不等于 `100%` 不做强制拦截：保存（新增持股关系、股权调整）时，若存在持股中股东且合计不等于 `100%`，弹窗提示「充电站持股数合计不等于100%，是否确认。」，用户确认后继续保存，取消则不保存；站点无持股中股东时不提示。

* 已退出关系不计入占比合计；同一股东可保留多条已退出历史记录，但同一站点仅允许一条持股中关系。

* 充电站详情页股东信息区域仅展示 `持股中` 记录：已退出股东及历史持股变化不展示在该区域，避免同一股东多次进出导致列表噪音；已退出记录由后续时间线统一承载。

* 退股时必须同步调整其他股东占比。

* 调整后合计不等于 `100%` 时，同样按保存确认提示口径处理。

* 股权调整立即生效，不额外指定未来生效时间。

## 8. 关键业务规则

### 8.1 新增充电站流程

采用“两段式录入”：

1. 先填写并保存站点基础信息。
2. 本阶段保存成功后先返回列表页，并在列表中展示新建站点。
3. 待充电站详情页 task 完成后，再补齐“保存后进入详情页”的完整流程。
4. 在详情页继续新增充电桩。
5. 在详情页继续建立股东与持股关系。

阶段性交付说明：

* 为尽快形成可验收的数据闭环，充电站管理阶段优先交付平台选择控件与新增充电站能力。

* 列表页的按名称搜索、按平台筛选、按状态筛选顺延到新增闭环完成后实现。

* 在充电站详情页交付前，新增成功后的默认落点为充电站列表页，而不是详情页。

### 8.2 删除策略

第一期不对业务对象执行删除。

* 充电站通过状态切换到 `停用` 管理。

* 充电桩通过状态切换到 `停用` 管理。

* 股东主档通过状态切换到 `停用` 管理。

* 持股关系通过 `已退出` 表示退股。

### 8.3 股权调整

股权调整为独立页面操作。

交互要求：

* 从充电站详情页股东分区进入。

* 独立页面展示该站全部股东及持股情况。

* 支持一次性修改多个股东占比。

* 保存前若持股占比合计不等于 `100%`，弹窗提示「充电站持股数合计不等于100%，是否确认。」，确认后继续保存。

* 保存后生成一条股权调整事件。

### 8.4 状态流转

* 充电站、充电桩为单一状态。

* 状态允许任意切换，不做流程强约束。

* 状态变更时原因备注可填可不填。

### 9.5 操作日志实现规范

操作日志采用 **AOP + 注解** 的方式统一记录，确保业务代码无侵入。

#### 9.5.1 核心组件

* **注解**：`@LogOperation`，标记需要记录日志的方法
* **切面**：`OperationLogAspect`，自动拦截带注解的方法并记录日志
* **服务**：`OperationLogService`，统一的日志写入服务
* **实体**：`OperationLog`，日志数据模型
* **枚举**：`OperationType`（CREATE/UPDATE/DELETE/EXIT）、`OperationTargetType`（STATION/PILE/SHAREHOLDER/SHAREHOLDING）

#### 9.5.2 使用规范

**适用场景**：

* 所有 CommandService 的写操作方法（新增、修改、删除、状态变更、退出等）
* 不适用只读操作（查询、列表、详情等）

**注解使用示例**：

```java
@LogOperation(
    targetType = OperationTargetType.STATION,
    operationType = OperationType.CREATE,
    targetIdSpEL = "#result.stationCode",
    targetNameSpEL = "#result.stationName",
    stationIdSpEL = "#result.id"
)
public Station createStation(StationCreateRequest request) {
    // 业务逻辑
    return stationRepository.save(station);
}
```

**SpEL 表达式规则**：

* `#result`：方法返回值，用于从返回的实体对象中提取属性
* `#参数名`：方法参数，用于从请求对象中提取属性
* 支持属性访问：`#result.id`、`#request.name`
* 支持字符串拼接：`#result.shareholder.shareholderName + '-' + #result.station.stationName`

**返回值要求**：

* 所有需要记录日志的 CommandService 方法必须返回实体对象（而非 ID）
* 这样才能通过 SpEL 从返回值中提取 `targetId`、`targetName`、`stationId` 等信息
* Controller 层调用 CommandService 后通过 `.getId()` 提取 ID 返回给前端

#### 9.5.3 开发检查清单

**新增写操作方法时必须**：

1. 方法返回实体对象（不要返回 Long ID）
2. 添加 `@LogOperation` 注解
3. 正确配置 `targetType` 和 `operationType`
4. 使用 SpEL 表达式正确提取 `targetIdSpEL`、`targetNameSpEL`
5. 如果是站点相关操作，配置 `stationIdSpEL`
6. 如果需要捕获操作前状态，设置 `captureBeforeState = true`
7. Controller 层调用后使用 `.getId()` 提取 ID

**常见错误**：

* ❌ 方法返回 Long ID
* ❌ 忘记添加 `@LogOperation` 注解
* ❌ SpEL 表达式错误（如 `#result.id` 写成 `#id`）
* ❌ Controller 直接返回实体对象而非 ID
* ❌ targetType 或 operationType 选择错误

**验证方法**：

1. 执行写操作后查询 `biz_operation_log` 表
2. 检查日志记录是否包含正确的操作人、对象类型、操作类型、目标ID/名称
3. 检查前后状态是否正确捕获（如需要）

## 10. 用户旅程

### 10.1 业务管理员新增充电站

1. 登录系统
2. 进入首页
3. 点击新增充电站
4. 填写并保存站点基础信息
5. 系统生成站点编号
6. 返回充电站列表并看到新建记录
7. 待详情页交付后，再进入站点详情
8. 新增充电桩
9. 新增或关联股东
10. 进入股权调整页完成占比配置
11. 返回详情查看时间线

### 10.2 业务管理员调整股权

1. 进入某充电站详情
2. 进入股东分区
3. 点击股权调整
4. 在独立页面一次性调整多个股东占比
5. 保存前校验总和
6. 保存成功后生成时间线和日志事件

### 10.3 系统管理员创建业务管理员

1. 使用 `admin` 登录
2. 进入用户管理
3. 填写手机号与初始密码
4. 保存生成业务管理员账号
5. 列表中可查看该账号最后登录时间
6. 后续可执行重置密码

### 10.4 系统管理员维护系统字典

1. 登录系统
2. 默认进入首页概览，随后进入系统字典
3. 切换到目标字典类型
4. 新增或修改字典项基础信息
5. 保存后立即可供业务页面选择或筛选
6. 系统记录字典维护日志

## 11. 移动端适配要求

* 使用同一套后台页面自适应兼容手机访问。

* 详情页采用纵向滚动分区，避免复杂多层标签。

* 表单在手机端需保证可输入、可点击、可滚动。

* 股权调整页在手机端采用更紧凑的纵向布局。

* 优先保障核心业务操作可完成，不额外做独立移动端设计体系。

## 12. 非功能要求

### 12.1 安全

* 密码不得明文存储。

* 公网访问必须完成账号鉴权。

* 用户登录成功后需记录最后登录时间。

* 重置密码必须记录日志。

* 菜单与接口都要执行角色鉴权。

### 12.2 可扩展性

* 充电桩模型需预留枪级扩展能力。

* 系统字典模型需预留后续扩展新的字典类型能力。

* 日志模型需兼容系统管理员与业务管理员事件。

### 12.3 易用性

* PC 端优先保证后台录入效率。

* 手机端优先保证可操作性。

* 时间线描述需能被业务人员直接理解。

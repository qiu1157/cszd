# 本人修改密码设计

## 1. 目标与范围

本设计用于落地里程碑 B 的 `实现本人修改密码功能` 任务。

当前任务在现有 `我的账号` 页面中接入“本人修改密码”能力，系统管理员与业务管理员均可使用。交互采用独立弹窗，不新增单独页面。

## 2. 交互方式

- 入口位置：`我的账号` 页的 `安全设置` 区域
- 交互形式：点击 `修改本人密码` 按钮后打开独立弹窗
- 弹窗关闭约束：
  - 不能点击遮罩关闭
  - 不能按 `Esc` 关闭
  - 仅能通过 `取消` 或 `确认修改` 完成交互

## 3. 弹窗结构

弹窗标题：`修改本人密码`

弹窗字段：

- 旧密码
- 新密码
- 确认新密码

底部按钮：

- `取消`
- `确认修改`

## 4. 前端校验规则

### 4.1 必填规则

以下字段均为必填：

- 旧密码
- 新密码
- 确认新密码

### 4.2 新密码规则

新密码必须满足以下要求：

- 长度为 `6-20` 位
- 必须同时包含字母和数字

### 4.3 一致性规则

- 确认新密码必须与新密码一致
- 新密码不能与旧密码相同

## 5. 后端规则

- 后端通过当前登录用户身份确定“本人”账号，不接受前端传入其他账号作为修改目标
- 后端必须校验旧密码是否正确
- 后端必须校验新密码是否满足 `6-20` 位且同时包含字母和数字
- 后端必须校验新密码不能与旧密码相同
- 校验通过后，使用现有密码哈希能力更新数据库中的密码

## 6. 成功后的处理

- 密码修改成功后，前端提示：`密码修改成功，请重新登录`
- 成功后清空当前登录态
- 成功后跳转登录页

这样可以确保当前 token 不继续沿用，避免用户在改密后仍保留旧登录态。

## 7. 失败提示口径

- 旧密码错误：明确提示旧密码不正确
- 新密码不合规：提示 `请输入6-20位且包含字母和数字的新密码`
- 确认新密码不一致：提示确认密码与新密码不一致
- 新旧密码相同：提示新密码不能与旧密码相同
- 其他异常：提示稍后重试

## 8. 页面联动要求

- 当前 `我的账号` 页面中的 `修改本人密码` 按钮从置灰改为可点击
- 修改密码成功后，由于会清空登录态并跳转登录页，因此无需保留弹窗状态
- 当前任务不改变 `我的账号` 页其他展示区块

## 9. 非本任务范围

以下内容不在当前任务内：

- 短信验证码校验
- 密码强度评分
- 密码历史重复限制
- 首次登录强制改密
- 修改密码操作日志的独立展示

## 10. 验收口径

- 系统管理员可在 `我的账号` 页面打开修改密码弹窗
- 业务管理员可在 `我的账号` 页面打开修改密码弹窗
- 旧密码错误时不能提交成功，并给出明确提示
- 新密码不满足规则时不能提交成功，并给出明确提示
- 确认新密码与新密码不一致时不能提交成功，并给出明确提示
- 密码修改成功后，当前登录态失效并跳转登录页
- 用户可使用新密码重新登录
- 用户不能继续使用旧密码登录

# 电表户号编辑保存报错 - 问题分析与解决方案

## 📋 问题描述

**现象**: 编辑充电站的电表户号后点击保存,系统提示"系统异常,请稍后重试"

**时间**: 2026-09-09

**影响范围**: 充电站编辑功能

---

## 🔍 问题分析

### 1. 根本原因

**数据库表结构与代码不同步**

- ✅ **代码层面**: 已完成所有改造
  - 前端表单已添加 `meterAccountNumber` 字段
  - 后端 Entity、DTO、Service、Controller 已支持该字段
  - API 请求和响应都包含该字段
  
- ❌ **数据库层面**: 缺少字段
  - `station` 表中没有 `meter_account_number` 字段
  - 当保存数据时,JPA 尝试写入不存在的字段,导致 SQL 异常
  - 异常被全局异常处理器捕获,返回"系统异常"

### 2. 异常链路

```
用户点击保存
  ↓
前端发送 PUT /api/stations/{id} 请求(包含 meterAccountNumber)
  ↓
后端 StationCommandService.updateStation() 
  ↓
JPA 生成 UPDATE SQL: UPDATE station SET ... meter_account_number = ? ...
  ↓
MySQL 执行失败: Unknown column 'meter_account_number' in 'field list'
  ↓
抛出 BadSqlGrammarException
  ↓
全局异常处理器返回: {"success": false, "message": "系统异常,请稍后重试"}
```

### 3. 为什么之前没发现

- 单元测试使用的是 Mock 对象,不依赖真实数据库
- 集成测试被 `@Disabled` 禁用了
- 开发时只进行了编译检查,没有端到端测试

## ✅ 解决方案

### 方案1: 手动执行数据库迁移(推荐)

**步骤1**: 连接到 MySQL 数据库

使用你的数据库管理工具(如 Navicat、DBeaver、phpMyAdmin)连接到目标数据库（连接信息请使用本地私有配置，不写入仓库）。

**步骤2**: 执行迁移脚本

```sql
USE <数据库名>;

-- 添加 meter_account_number 字段
ALTER TABLE station 
ADD COLUMN meter_account_number VARCHAR(64) DEFAULT NULL 
COMMENT '电表户号；用于匹配电费发票，记录每月电费情况' 
AFTER contact_phone;

-- 验证字段已添加
DESCRIBE station;
```

**步骤3**: 验证功能

1. 刷新浏览器页面
2. 编辑任意充电站,填写电表户号
3. 点击保存
4. 验证保存成功,刷新后电表户号仍然存在

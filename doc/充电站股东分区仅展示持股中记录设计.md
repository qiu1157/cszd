# 充电站股东分区仅展示持股中记录设计

## 1. 背景与问题

当前充电站详情页「股东信息」分区（`StationShareholderSection.vue`）会同时展示某股东的全部持股关系记录，包括：

- `ACTIVE`：当前正在持股的记录
- `EXITED`：已退出的历史记录

以充电站 `ST-202608-0005` 为例，股东「长沙众电」在该站同时出现「持股中」与「已退出」两行数据。随着业务推进，同一股东可能发生多次持股、退股、再持股，导致详情页股东信息区域噪音过大，难以快速识别当前股权结构。

## 2. 设计目标

- **充电站详情页的股东信息区域只展示当前持股中股东**，已退出股东与历史持股变化不再出现在该区域。
- **不改变「不删除」原则**：已退出记录继续保留在 `biz_shareholding` 表中，作为历史痕迹。
- **为里程碑 G 时间线预留数据**：未来通过时间线统一展示持股、退股、股权调整等历史变更。
- **接口语义清晰**：查询接口支持按状态筛选，当前页面传 `ACTIVE`，时间线可复用同一接口查全部或已退出记录。

## 3. 方案选型

采用「方案 3：接口参数化过滤」。

| 方案 | 说明 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| 前端过滤 | 接口返回全部状态，前端只渲染 `ACTIVE` | 改动最小 | 网络层仍传已退出数据；接口语义模糊 | 不采用 |
| 后端过滤 | 接口只返回 `ACTIVE`，前端原样展示 | 语义干净 | 已退出记录当前无查询入口 | 不采用 |
| 接口参数化 | 接口增加状态参数，前端按需传 `ACTIVE` | 语义清晰且为时间线预留能力 | 改动量适中 | **采用** |

## 4. 数据保存方案

### 4.1 表结构

继续使用现有 `biz_shareholding` 表，不做物理删除。

```sql
CREATE TABLE IF NOT EXISTS biz_shareholding (
  id BIGINT NOT NULL AUTO_INCREMENT,
  station_id BIGINT NOT NULL COMMENT '充电站ID',
  shareholder_id BIGINT NOT NULL COMMENT '股东ID',
  ownership_percentage DECIMAL(5,2) NOT NULL COMMENT '股份占比',
  holding_status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE 持股中 / EXITED 已退出',
  effective_at TIMESTAMP NULL DEFAULT NULL COMMENT '生效时间',
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_biz_shareholding_shareholder_status (shareholder_id, holding_status),
  KEY idx_biz_shareholding_station (station_id)
) ENGINE=InnoDB;
```

### 4.2 反复持股/退股的数据形态

- **退股**：将原 `ACTIVE` 记录更新为 `EXITED`，不删除。
- **退出后再次关联**：允许新增一条 `ACTIVE` 记录，旧的 `EXITED` 记录保留。
- **同一时刻唯一性**：同一站点、同一股东只能存在一条 `ACTIVE` 记录，由应用层校验。

示例：

| id | station_id | shareholder_id | ownership_percentage | holding_status | 业务含义 |
|----|-----------|---------------|---------------------|----------------|---------|
| 1  | 5         | 10            | 60.00               | EXITED         | 第一次持股，后退出 |
| 2  | 5         | 10            | 40.00               | ACTIVE         | 退出后再次持股 |

### 4.3 应用层唯一性校验

`ShareholdingCommandService.createShareholding` 已存在校验：

```java
if (holdingStatus == HoldingStatus.ACTIVE
        && shareholdingRepository.existsByStationIdAndShareholderIdAndHoldingStatus(
                validStationId, shareholderId, HoldingStatus.ACTIVE)) {
    throw new BusinessException("SHAREHOLDING_DUPLICATE", "该股东已是持股中状态，无需重复关联", HttpStatus.BAD_REQUEST);
}
```

该逻辑保持不变。

## 5. 接口变更

### 5.1 后端：ShareholdingQueryService

`getStationShareholdings(Long stationId)` 增加可选状态参数：

```java
public List<StationShareholdingListItemResponse> getStationShareholdings(Long stationId, HoldingStatus holdingStatus)
```

- 当 `holdingStatus` 为 `null` 时，返回全部记录（供时间线使用）。
- 当 `holdingStatus` 为 `ACTIVE` 时，仅返回持股中记录（供站点详情股东分区使用）。
- 当 `holdingStatus` 为 `EXITED` 时，仅返回已退出记录（供时间线筛选使用）。

### 5.2 后端：ShareholdingController

`GET /api/stations/{stationId}/shareholdings` 增加可选查询参数 `holdingStatus`：

```java
@GetMapping("/stations/{stationId}/shareholdings")
public ApiResponse<List<StationShareholdingListItemResponse>> getStationShareholdings(
        @PathVariable Long stationId,
        @RequestParam(required = false) String holdingStatus
) {
    // ...
}
```

参数值只接受 `ACTIVE` / `EXITED`，非法值返回 400。

### 5.3 前端：API 层

`getStationShareholdings(stationId: number)` 改为支持可选状态参数：

```typescript
export function getStationShareholdings(
  stationId: number,
  holdingStatus?: 'ACTIVE' | 'EXITED'
): Promise<StationShareholdingListItemResponse[]>
```

### 5.4 前端：StationShareholderSection

站点详情股东分区调用：

```typescript
shareholdings.value = await getStationShareholdings(props.stationId, 'ACTIVE')
```

空态文案同步调整为：「暂无持股中股东，点击右上角“关联股东”开始维护。」

## 6. 前端展示口径

### 6.1 站点详情股东分区

- 只渲染 `holdingStatus === 'ACTIVE'` 的记录。
- 不展示「已退出」标签与相关行。
- 占比合计警示仍基于持股中记录计算（与现有逻辑一致）。
- 退股入口继续只对 `ACTIVE` 行开放（逻辑不变）。

### 6.2 股权调整独立页面

股权调整页 already 只应调整持股中关系，本次保持只查询 `ACTIVE`。

### 6.3 股东详情关联站点列表

`ShareholdingQueryService.getShareholderStations` 已只查 `ACTIVE`，保持现状。

## 8. 验收标准

- [ ] 站点详情股东信息区域仅展示持股中股东。
- [ ] 已退出股东不在充电站详情股东信息区域出现。
- [ ] 同一股东退出后再次关联，站点详情只显示最新持股中记录。
- [ ] 退股操作后，站点详情股东分区立即刷新，已退出股东消失。
- [ ] 占比合计警示仍只基于持股中记录计算。
- [ ] 关联股东时若该股东已是持股中状态，仍提示「该股东已是持股中状态，无需重复关联」。
- [ ] 已退出数据仍保留在数据库中，不物理删除。

# 项目文档导航

本目录按「需求 → 设计 → 开发 → 部署 → 测试 → 归档」分层组织。开发遵循文档驱动：先读需求与设计，按任务拆解推进，用验收清单统一验收。

## 目录结构

| 目录 | 用途 | 关键文档 |
|------|------|---------|
| [`requirements/`](requirements/) | 需求文档：业务目标、角色权限、页面结构、业务规则 | `需求说明书.md` |
| [`design/`](design/) | 设计文档：系统规格、前端规范、特性设计 | `系统规格说明.md`（权威规格）、`前端开发规范.md` |
| [`development/`](development/) | 开发 Task 文档：任务拆解、验收清单、开发流程 | `任务拆解.md`、`验收清单.md`、`开发流程与规范.md` |
| [`deployment/`](deployment/) | 生产部署与运维 | `部署指南.md` |
| [`testing/`](testing/) | 测试报告（里程碑 J 产物） | `J.2` ~ `J.7` |
| [`archive/`](archive/) | 历史归档：已实现特性的设计、实施计划、修复与排查记录 | 见归档说明 |

## 阅读顺序

1. **了解业务**：`requirements/需求说明书.md`
2. **掌握规格与约束**：`design/系统规格说明.md` + `design/前端开发规范.md`
3. **了解开发流程**：`development/开发流程与规范.md`
4. **按任务推进**：`development/任务拆解.md` → `development/验收清单.md`
5. **部署上线**：`deployment/部署指南.md`

## 强约束

- UI/交互以 `prototype/charging-station-system-prototype.html` 为第一期基准。
- 需求/范围变更必须先同步更新 `requirements/` 与 `design/`，再同步 `development/` 的任务与验收项。
- 每完成一个 task 执行一次 conventional commit。
- 仓库公开托管，任何文档禁止出现真实密码、密钥、Token、公网地址、业务/个人隐私数据。

## 归档说明（archive/）

归档目录保留历史决策与问题记录，供追溯，**不再是当前权威口径**（以 `design/` 为准）：

- `系统字典管理列表页设计.md` 与 `系统字典页改版设计.md`：字典页两次迭代，最终以「改版设计」（顶部下拉）为准。
- `操作日志实现与排查记录.md`：操作日志 AOP 实现与两次关键修复（JPQL 字段引用、事务传播）。
- `本人修改密码设计.md`、`我的账号页面设计.md`：里程碑 B 特性设计，规则已并入规格说明。
- `充电站股东分区展示优化实施计划.md`：持股中记录展示优化的 TDD 实施步骤。
- `电表户号保存报错问题分析.md`：电表户号字段缺失的排查与迁移记录。

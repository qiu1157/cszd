# 充电站管理系统规格说明

## 1. 文档目标

本文件用于定义充电站管理系统第一期的产品范围、业务规则、页面结构、角色权限、核心数据模型和技术基线，作为后续任务拆解与开发验收的统一依据。

## 2. 产品定位

建设一个面向内部管理人员使用的充电站管理系统，支持公网访问，采用统一 Web 后台同时兼容 PC 与手机自适应访问。

第一期目标：

- 支持充电站、充电桩、股东、持股关系的统一管理。
- 支持系统管理员与业务管理员的权限分工。
- 支持关键业务事件、状态变更、账号与平台维护的日志审计。
- 支持在页面内查看历史变化时间线。
- 为后续外部平台对接和单枪扩展预留数据结构。

## 3. 范围定义

### 3.1 本期包含

- 登录与密码管理
- 首页数据概览
- 平台字典管理
- 用户管理
- 充电站管理
- 充电桩管理
- 股东主档管理
- 持股关系管理
- 股权调整独立页面
- 全局操作日志
- 站点详情时间线
- 股东详情时间线
- PC 与手机自适应后台

### 3.2 本期不包含

- 用户注册
- 短信验证码登录
- 微信扫码登录
- 外部平台接口对接
- 平台接口参数维护
- 单枪级页面管理
- 独立手机端应用
- 复杂版本快照还原

## 4. 角色与权限

### 4.1 系统管理员

- 默认账号：`admin`
- 默认密码：`123456`
- 可登录系统
- 可修改本人密码
- 可创建业务管理员
- 可重置业务管理员密码
- 可启用或停用业务管理员
- 可维护平台字典
- 可查看全局操作日志
- 不允许维护充电站、充电桩、股东、持股关系等业务数据

### 4.2 业务管理员

- 使用手机号作为登录账号
- 由系统管理员手工创建
- 首次登录不强制修改初始密码
- 可修改本人密码
- 可维护全部充电站业务数据
- 可维护全部充电桩业务数据
- 可维护股东主档
- 可建立与调整持股关系
- 可查看全局操作日志

### 4.3 数据权限

- 业务管理员为全站可管模式。
- 所有业务管理员可查看并维护所有充电站、充电桩、股东及持股关系。

## 5. 技术基线

- 前端：`Vue 3 + Element Plus`
- 后端：`Java`
- 数据库：`MySQL`
- 部署方式：公网部署
- 登录方式：账号密码登录
- 终端策略：同一套 Web 后台自适应兼容 PC 与手机

## 6. 信息架构

### 6.1 顶层菜单

- 首页
- 充电站管理
- 股东管理
- 平台管理
- 操作日志
- 用户管理
- 我的账号

### 6.2 首页

首页采用“数据概览 + 快捷入口”模式。

展示内容：

- 充电站总数
- 充电站状态统计
- 充电桩总数
- 充电桩状态统计
- 股东总数
- 最近操作记录

快捷入口：

- 新增充电站
- 进入股东管理
- 查看操作日志
- 进入平台管理

### 6.3 充电站管理

采用 `列表 + 详情页` 结构。

列表页能力：

- 按名称搜索
- 按平台筛选
- 按状态筛选
- 分页浏览
- 进入详情
- 新增充电站

详情页采用单页分区结构，包含：

- 基础信息
- 充电桩管理
- 股东信息
- 历史变化时间线

### 6.4 股东管理

股东为独立实体，需提供独立菜单。

列表页能力：

- 按股东名称搜索
- 按状态筛选
- 新增股东
- 编辑股东
- 进入股东详情

股东详情页能力：

- 查看股东基础信息
- 查看该股东关联的充电站
- 查看该股东的历史变化时间线
- 时间线默认展示全部站点事件
- 支持按充电站筛选

### 6.5 平台管理

平台管理为独立字典页面，仅系统管理员可维护。

第一期维护字段：

- 平台名称
- 平台编码或简称
- 平台状态

### 6.6 用户管理

仅系统管理员可见。

支持：

- 新增业务管理员
- 查看业务管理员列表
- 重置业务管理员密码
- 启用或停用业务管理员

### 6.7 操作日志

提供独立全局日志中心。

支持：

- 按时间筛选
- 按操作人筛选
- 按对象类型筛选
- 按充电站筛选
- 查看事件详情

## 7. 核心实体设计

### 7.1 平台

字段建议：

- 主键ID
- 平台名称
- 平台编码
- 平台状态
- 创建时间
- 更新时间

说明：

- 平台作为字典数据供充电站选择。
- 第一阶段不保存 API 地址、密钥等对接参数。

### 7.2 充电站

字段建议：

- 主键ID
- 充电站名称
- 系统ID
- 平台ID
- 所在平台
- 地址
- 联系人
- 生命周期状态
- 创建时间
- 更新时间

规则：

- `系统ID` 系统自动生成，且全局唯一。
- `平台ID` 人工录入，可为空。
- `平台ID` 在同一平台内唯一。
- 所在平台必须从平台字典中选择。

生命周期状态：

- 签合同
- 建设中
- 运营中
- 运营异常
- 停用

状态规则：

- 单一状态
- 允许任意切换
- 状态变更备注为可选
- 新增默认状态为 `签合同`

### 7.3 充电桩

字段建议：

- 主键ID
- 桩编号
- 所属充电站ID
- 充电类型
- 充电枪数量
- 生命周期状态
- 创建时间
- 更新时间

规则：

- 当前管理粒度为桩级，不管理单枪明细。
- 需预留未来扩展到枪级的能力。
- 桩编号由系统自动生成。
- 桩编号全局唯一。

生命周期状态：

- 运营中
- 运营异常
- 停用

状态规则：

- 单一状态
- 允许任意切换
- 状态变更备注为可选
- 新增默认状态为 `运营中`

### 7.4 股东主档

字段建议：

- 主键ID
- 股东名称
- 联系人
- 联系电话
- 状态
- 创建时间
- 更新时间

规则：

- 股东为独立主档实体。
- 一个股东可关联多个充电站。
- 同一股东在不同充电站共享同一份主档信息。

状态：

- 启用
- 停用

说明：

- `退股` 不属于股东主档状态。
- 退股发生在持股关系层面。

### 7.5 持股关系

字段建议：

- 主键ID
- 充电站ID
- 股东ID
- 股份占比
- 关系状态
- 生效时间
- 创建时间
- 更新时间

关系状态：

- 持股中
- 已退出

规则：

- 同一充电站下所有 `持股中` 股东的股份占比总和必须等于 `100%`。
- 退股时必须同步调整其他股东占比。
- 调整后仍需满足总和为 `100%`。
- 股权调整立即生效，不额外指定未来生效时间。

## 8. 关键业务规则

### 8.1 新增充电站流程

采用“两段式录入”：

1. 先填写并保存站点基础信息。
2. 保存成功后进入站点详情页。
3. 在详情页继续新增充电桩。
4. 在详情页继续建立股东与持股关系。

### 8.2 删除策略

第一期不对业务对象执行删除。

- 充电站通过状态切换到 `停用` 管理。
- 充电桩通过状态切换到 `停用` 管理。
- 股东主档通过状态切换到 `停用` 管理。
- 持股关系通过 `已退出` 表示退股。

### 8.3 股权调整

股权调整为独立页面操作。

交互要求：

- 从充电站详情页股东分区进入。
- 独立页面展示该站全部股东及持股情况。
- 支持一次性修改多个股东占比。
- 保存前校验总和必须等于 `100%`。
- 保存后生成一条股权调整事件。

### 8.4 状态流转

- 充电站、充电桩为单一状态。
- 状态允许任意切换，不做流程强约束。
- 状态变更时原因备注可填可不填。

## 9. 历史变化与日志审计

### 9.1 展示方式

统一采用 `时间线事件流`。

特点：

- 按时间倒序展示
- 每条事件显示摘要
- 支持查看事件详情
- 不做版本快照主视图
- 不做字段 Diff 主视图

### 9.2 展示位置

- 充电站详情页
- 股东详情页
- 操作日志页

### 9.3 日志覆盖范围

业务管理员操作：

- 新增与修改充电站
- 充电站状态变更
- 新增与修改充电桩
- 充电桩状态变更
- 新增与修改股东主档
- 股东主档状态变更
- 建立持股关系
- 持股关系退出
- 股权调整

系统管理员操作：

- 新增业务管理员
- 重置业务管理员密码
- 启用或停用业务管理员
- 新增与修改平台字典
- 平台状态变更

### 9.4 日志字段建议

- 操作时间
- 操作账号
- 操作角色
- 对象类型
- 对象标识
- 操作类型
- 修改前内容
- 修改后内容
- 备注

## 10. 用户旅程

### 10.1 业务管理员新增充电站

1. 登录系统
2. 进入首页
3. 点击新增充电站
4. 填写并保存站点基础信息
5. 系统生成站点系统ID
6. 跳转到站点详情
7. 新增充电桩
8. 新增或关联股东
9. 进入股权调整页完成占比配置
10. 返回详情查看时间线

### 10.2 业务管理员调整股权

1. 进入某充电站详情
2. 进入股东分区
3. 点击股权调整
4. 在独立页面一次性调整多个股东占比
5. 保存前校验总和
6. 保存成功后生成时间线和日志事件

### 10.3 系统管理员创建业务管理员

1. 使用 `admin` 登录
2. 进入用户管理
3. 填写手机号与初始密码
4. 保存生成业务管理员账号
5. 后续可执行重置密码

### 10.4 系统管理员维护平台字典

1. 登录系统
2. 进入平台管理
3. 新增或修改平台基础信息
4. 保存后立即可供充电站表单选择
5. 系统记录平台维护日志

## 11. 移动端适配要求

- 使用同一套后台页面自适应兼容手机访问。
- 详情页采用纵向滚动分区，避免复杂多层标签。
- 表单在手机端需保证可输入、可点击、可滚动。
- 股权调整页在手机端采用更紧凑的纵向布局。
- 优先保障核心业务操作可完成，不额外做独立移动端设计体系。

## 12. 非功能要求

### 12.1 安全

- 密码不得明文存储。
- 公网访问必须完成账号鉴权。
- 重置密码必须记录日志。
- 菜单与接口都要执行角色鉴权。

### 12.2 可扩展性

- 充电桩模型需预留枪级扩展能力。
- 平台模型需预留后续外部平台对接扩展能力。
- 日志模型需兼容系统管理员与业务管理员事件。

### 12.3 易用性

- PC 端优先保证后台录入效率。
- 手机端优先保证可操作性。
- 时间线描述需能被业务人员直接理解。
